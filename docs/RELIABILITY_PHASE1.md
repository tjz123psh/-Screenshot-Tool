# 产品化第一批：可靠性修复

本轮按用户批准的路线实施，不重构整个项目、不恢复 niri 快捷键。已于 2026-10-04 完成统一验证并安装到本机；四个已安装程序与通过验证的 release 构建逐字节一致，三个用户服务已重启且正常运行。

## 已实现的行为

### 图片落盘

- 覆盖保存先在目标目录创建 0600 独占临时文件，完整写入并同步，再提交替换；提交前失败不截断旧文件。
- 自动保存以独占提交发布完整图片，不覆盖同时出现的同名文件；不支持该文件系统操作时明确失败，而非降级成不安全覆盖。
- “已提交但目录同步未确认”是独立可识别状态，不能再说从未保存；调用方保留图像或恢复副本并显示警告。
- 提交后不再删除失去归属的临时路径；清理前核对设备号/inode，临时名分配有次数上限。不能把这些规则夸大为恶意共享目录中的无竞争 unlink 或整个文件系统的断电事务。

### 图片交接与恢复

- 子进程创建不再等于成功。图像解码成功、窗口状态建立并映射后才发一次性接管回执；拒绝/早退/超时不清理唯一副本。
- 恢复资源仅存在用户私有状态目录，验证请求ID、协议、文件归属、私有权限及图像inode；不递归删除用户传入目录。
- 正常接管后清理本次临时资源；失败副本不自动过期删除，需用户明确清理。这不是默认截图历史库，副本也是已标注的成品图，不包含隐藏原图工程。
- `vellum recover list` 列出编号，`vellum recover open ID` 重新打开，`vellum recover discard ID` 明确丢弃该副本；打开不会自动删除。
- 如果连恢复PNG都无法创建，保有RGB图的截图进程进入内存恢复预览，不假称已经落盘。保持窗口打开可另存或重试；仅这条异常路径控制服务仍忙。系统无法建窗或进程被强杀等更深层故障，不能承诺内存图片在断电后仍可恢复。
- 长图完整性、保存结果、复制结果分开显示。输出未完成使用独立退出状态，不再被服务误报成截图启动失败。

### 设置一致性

- 工作台启动截图时读取最新输出偏好；托盘和工作台不再以旧快照相互覆盖。
- 保存采用基础值/本次修改/最新值的逐字段合并，锁内重读；同字段冲突明确报出，不静默覆盖。
- 两层设置都有私有唯一临时文件和有界跨进程锁，写事务拒绝损坏的现有文档，不拿默认值覆盖坏文件；普通只读加载仍保留既有容错。
- 配置和输出偏好不是跨文件崩溃事务；第二文件失败明确提示部分保存。手工编辑器若不遵守应用锁，仍需冲突核对。

### 剪贴板与窗口响应

- 实际启用 PNG、JPEG、WebP 解码，保留 PNG 优先；使用独立生成的真实格式夹具验证。PNG 仍是输出格式，不等于新增 JPEG/WebP 导出选项。
- 读取错误区分无图片、格式不支持、损坏、命令失败、超时与过量。子进程读写共享10秒期限，输入/输出及解码后的RGB有大小限制，失败会终止进程组并回收直接子进程。
- 钉图保存/复制、结果文字复制转到后台，独立忙碌和错误反馈，重复操作有保护。关闭窗口不回写控件，但应用保持运行直到实际后台任务完成/超时收尾。

### OCR、翻译和诊断

- 直接翻译入口失败后可在原窗口重试翻译；OCR失败支持同图重试。保留手工编辑文字，新识别结果不会无声覆盖。
- 同一工作流共享总预算，单阶段只可收紧预算；后备模型不再重复领取完整超时时间。
- 取消会阻止后续请求和迟到结果；真实工作未结束前占位仍保留，不能连续取消后无限创建线程。同步网络或本地OCR不能被这个令牌立刻强杀，界面如实等待当前调用结束。网络受剩余预算约束，本地OCR还受30秒上限；本地计算、系统调度、回收和底层DNS线程另有边界，不承诺零延迟终止。
- 上游错误只显示固定安全分类，诊断默认不显示完整端点、代理地址或私有模型名称；不把裁短原始错误当作脱敏。普通OCR/翻译继续使用已遮挡合成后的图像。
