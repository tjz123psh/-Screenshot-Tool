# 全局快捷键、参考风格与快速滚动验证

> 此文保留前一轮验收记录；当前界面、快捷键入口与可靠性修复以[最新复查](<REFINEMENT_REVIEW.md>)为准。

## 1. 标准快捷键：实现、验证与本机限制

应用已接入 [XDG GlobalShortcuts](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.GlobalShortcuts.html)：原生应用身份注册、持久会话、系统授权、实际组合键读取、按住去重、关闭/停用、Portal 重启后自动重连。版本 2 可打开系统配置窗口；版本 1 返回明确错误，不伪装成支持再次配置。

快捷键进程是现有 UI 二进制的无窗口 Gio 模式，不新增安装二进制；带用户服务、D-Bus 激活与登录自启入口。未启用时不会弹授权窗口。旧桌面绑定只保留、不自动删除。

### 已修的竞争：迟到的授权回复

系统关闭会话后，若之前的授权请求仍在飞行中，迟到的成功回复会把状态改回“已生效”，而按键其实已经无效。修复方式是在会话关闭时取消本会话的待完成请求。该竞争由私有总线测试先复现、再修复。

### 为什么不用键盘抑制或注入协议冒充

本机同时公开 zwp_keyboard_shortcuts_inhibit_manager_v1 与 zwp_virtual_keyboard_manager_v1。前者只能在本窗口聚焦时抑制别人的快捷键，后者是注入输入，两者都无法注册一个应用未聚焦时仍能触发的全局组合键，因此不采用，也不在文档里写成“已支持全局快捷键”。

### 私有总线上的完整触发链路验证

[测试脚本](../tests/portal-shortcuts.py)使用真正的 Gio 客户端、隔离的 dbus-daemon、标准接口模拟器，以及真实编译出的 vellum-ui 与 vellumctl。它把 HOME、XDG 与运行时目录全部指向一次性临时目录，并用一个只会写标记文件的替身代替完整 CLI，因此任何失败都不会落到真实截图或真实配置。

覆盖内容：

- 绑定结果以系统返回为准，不假定首选组合键；可选 ListShortcuts 失败仍能完成授权。
- 按住重复只触发一次；释放后可再次触发；未注册的按键与不匹配的会话一律忽略。
- 部分授权显示为 partial；跨进程重启（ReleaseName 与 RequestName）后自动重连并重新绑定。
- 用户拒绝授权后状态为 denied，偏好写回 enabled 为 false，文件权限 0600。
- 会话关闭后迟到成功不再复活；再次启用不会被卡住（回归已加入测试）。
- 版本 1 明确拒绝 ConfigureShortcuts 且 can_configure 为 false；版本 2 正常转发。
- 真实分发：门户信号经过真实 vellumctl 到达私有控制 socket。长截图开始与结束成对出现，区域截图收到忙碌拒绝，钉图不继承截图输出参数。

## 2. 本机为什么仍然没有可用快捷键

以下都是本机实测，不是推测：

- 门户 GlobalShortcuts 只公开 version 1；已安装后端里只有 gnome.portal 声明实现该接口，而 niri-portals.conf 的 default 取值把 gnome 排在 gtk 之前。
- GNOME 后端依赖 org.gnome.Shell 的 GrabAccelerators；本会话 NameHasOwner org.gnome.Shell 返回 false，因此绑定请求被后端拒绝。
- niri 自身没有运行时注册快捷键的 IPC（niri msg 只有 action、output、event-stream 等，没有 bind），所以“不改配置”在 niri 上的唯一标准途径就是门户，而门户在本机当前不可用。

结论：代码与协议都已就绪且经过验证，但本机当前无法通过标准途径真正绑定。不为此启动 GNOME Shell、不申请 root 读输入设备、不偷偷改 niri 配置。

### 桌面不支持时的显式兜底

设置页「快捷键」提供「使用兼容方式…」：仅在状态为 unavailable 或 closed 时可用（fallback_offered 规则，含单元测试），点击后弹确认框，说明会写入合成器配置。实际写入复用既有安装路径（vellum shortcuts install）：写入前备份、检测到冲突时整组不写、验证失败回滚。它从不自动执行；标准后端可用时按钮保持禁用，不会引导用户去改一个本来正常的配置。

## 3. 参考图视觉方向

参考用户提供的烟灰磨砂、低饱和暖金、暖浅色文字与紧凑设置面板：移除大宣传区，改为真实截图模式按钮、对齐信息行、约 640×450 的窗口；不复制假的 macOS 控制按钮或未实现的全屏/窗口截图功能。设置窗口会探测标准 ext-background-effect-v1 请求合成器模糊，详见[原生验收](NATIVE_CAPTURE_AND_BLUR.md)。

## 4. 快速滚动：已经建立的证据

[高速保护回归](../crates/vellum-stitch/tests/fast_scroll.rs)覆盖变速、急停、反向、浏览器文本的大步滚动和无法可靠匹配的跳转。

- 旧实现曾把无实际重叠的相似文本追加 348 行；已新增相对像素改善检查。
- 真实浏览器滚轮帧曾在 480 高视口内跳 420 像素、只剩 60 行重叠，被误当成 236 像素位移并复用错误卡片；已新增相近候选的歧义拒绝，且不允许 robust 裁行把歧义洗成“正确”。两张真实合成页面帧已保留为确定性回归。
- 被拒绝的画面进入“校准/减速”提示，不再错报成“等待滚动”；未能接上的末尾会产生专门提示，并持续显示在图片查看器里。
- 700 高视口的滚轮序列（81 帧、最大相邻位移 370 像素、含停顿与反向）在线与默认重建结果均与参考页逐像素一致；480 高视口的更极端序列（最大相邻位移 420 像素）逐帧验证已确认图像前缀未被污染，这是安全失败，不代表补回了未采到的内容。

位置标记位于画面最左 4 列，校验时先裁掉左 8 列，拼接器无法“作弊”。最初的 Playwright 截图在持续滚动时会因页面裁剪竞争产生白条；最终改用不带页面裁剪的 CDP 固定视口截图，避免测试工具自己制造假撕裂。

真实采集链路的端到端结果（52 次成功采集、48 帧拼接、队列峰值 1、最大通道差 0）见[原生验收](NATIVE_CAPTURE_AND_BLUR.md)。

## 5. 复现命令

~~~sh
python3 tests/portal-shortcuts.py --dispatch
python3 tests/portal-shortcuts.py --dispatch --portal-version 1
python3 tests/portal-shortcuts.py
cargo test --locked --release --workspace
~~~

[测试网页](../tools/fast-wheel-fixture.html)是滚轮驱动的可重复合成场景；这不等于任意网站、任意速度、任意选区都能保证完整。完全重复内容、超过采样能力的瞬移、尚未加载的页面内容，仍有无法从截图恢复的信息。不得写“任何速度绝不撕裂”。
