# 连续产品化执行计划

用户要求：虽然分批实施，但不要在一批结束后停下来等待新的批准；每批验证通过后安装，再继续下一批。总目标只有在以下计划均完成并有证据时才关闭。

## 已完成：第一批可靠性

安全写图、跨进程接管与恢复、设置合并、有界剪贴板与JPEG/WebP解码、后台I/O、重试/取消/总预算、诊断脱敏、长图分项状态。已全量测试、原生检查并安装，见[记录](<RELIABILITY_PHASE1.md>)。

## 第二批：会话与日常操作（进行中）

1. 会话内图片文档、版本与可编辑标注；已有PNG只作为背景，不能声称恢复旧对象。
2. 独立编辑窗口支持继续标注、选中/移动/调整原对象、文字修改和再裁切；撤销重做及实色遮挡的安全边界保留。
3. 截图/长图/查看器/结果窗口贯通编辑、OCR、翻译、保存、复制和钉图；旧结果注明旧版本，迟到任务不得冒充新版本。
4. 源图与编辑草稿默认仅在本次会话内存/匿名进程通道中传递；普通PNG、剪贴板、钉图、OCR与恢复图片只用合成成品，不附加原图工程。
5. 输出目录、文件命名与预览偏好统一；新设置仍用第一批的三方合并和事务保护。
6. 将长图/编辑资源限制前置，保留可用结果，避免采集到最后才发现无法显示；声明真实测量范围。
7. 完整回归、必要原生检查、备份安装，随后继续第三批。

## 第三批：可追踪发布与安全交付（待做）

1. 版本/构建标识、可验证单一发布包，开发源码通道与正式包区分。
2. 整套版本准备后切换，激活检查、上一版回退、并发安装锁和中断恢复；不强杀未保存窗口。
3. 安装清单与安全卸载，默认保留配置/截图/恢复数据，不动niri配置和共享系统依赖。
4. 默认脱敏支持报告、明确安装结果与已验证支持平台。
5. 自动化故障矩阵与本机原生交付验收；无法实测的平台明确标为实验/未验证，不假称全部兼容。
6. 验证后安装并给出整体完成证据。

每批源码改动由Agent Team按不重叠文件范围实现，Lead统一检查和安装。每批完成只更新进度，不提前关闭总目标。
