# 第三批：可追踪版本与安全交付

本批已完成版本化安装、回退、卸载、构建身份和发布候选生成，并于2026-10-05在本机完成迁移与回退验收。所有破坏性故障测试先在临时目录与假服务里运行；最终安装为0.2.0开发构建，来源有未提交改动，不冒充正式公开发布。

## 版本与来源

- 工作区升级到0.2.0。四个程序共享同一份编译期BuildInfo，支持无GUI/无服务初始化的 `--build-info-json`。
- 身份覆盖源文件、资源与安全构建输入摘要、commit、dirty/unknown、目标与编译器；不会把未知来源或本地修改冒充干净tag。
- 工作台“关于”与命令行可查看实际版本。受管程序只从自身版本目录启动配套程序、读取资源，不在文件损坏时悄悄跳到PATH另一版。
- 当前仓库有未提交的开发改动，因此本机生成的是开发包；未擅自创建tag、推送代码或公开发布。

## 包与安装

- 打包器验证四个二进制的固定标记和完整构建信息一致，按明确白名单打包，不含用户配置、截图、恢复图片或源码工程。
- 每个成员记录大小、权限类型和SHA256；拒绝未知/缺失成员、路径跳转、符号链接、特殊文件、哈希错误和超限输入。归档排序、时间与头部固定，相同输入可生成相同归档。
- 发行包入口不构建、不联网，只调用包内同一版本管理器。开发源码入口则先构建验证包，再委托管理器；源码与构建缓存保留。
- 默认版本根为用户的.local/lib/vellum，完整版本位于releases/id，current链接一次切换；用户入口与资源由清单管理。
- systemd服务固定到候选版本执行，桌面/自启动/DBus入口使用稳定公共入口，避免缓存把新启动固定到旧版本。
- 原有普通文件安装需明确adopt-legacy；先完整备份，不把未知冲突文件静默覆盖。用户配置和图片从来不是安装清单成员。

## 状态、失败与恢复

- 同一锁覆盖安装、回退、修复、卸载；持久日志记录阶段。中断恢复不依赖退出trap一定运行。
- ready、已安装待激活、需要修复、成功回退、激活失败但已补偿分别表达；主动回退成功为退出0，激活失败补偿不假报成功。
- 有窗口、截图或未受用户服务管理的独立旧daemon时安全延期，不自动强杀。管理器给出可实际运行的repair程序与参数，不假设旧CLI已有新命令。
- 延期后重新读取用户服务策略，不能用过期快照覆盖后来做出的enabled/active选择。
- 服务不可达时可准备/安装文件，但不称运行就绪；这类待激活安装仍能明确卸载/取消，不要求先恢复服务。旧式尚未接管的延期仅撤候选，原普通文件与正在运行的旧程序保持原状。
- 重启前核实实际FragmentPath，允许同根中凭据和哈希通过的旧版本缓存；拒绝全局/其他实例单元及错误角色的活动进程，重启后核实MainPID程序属于候选版本。
- 回退只切程序和资源，不用旧配置副本覆盖用户的新设置；自定义实例的管理命令要使用自身记录，不能误操作HOME下另一默认实例。

## 卸载

明确确认后仅清理可验证且未在用的程序与入口；逐成员校验，不递归删除未知目录。旧式备份、用户改动、未知成员和在用版本保留并报告。配置、截图、恢复数据、niri/Hyprland配置及共享系统依赖默认不删除。中断的清理可继续，元数据最后处理。

## 通信与支持报告

- 受管客户端在同一连接上先核身份再发截图任务，服务也再次检查；版本/协议/受管状态不匹配明确拒绝，不能自动换另一版或重发不确定是否成功的任务。
- Status/Ping/Shutdown仍能用于管理迁移；开发目录兼容规则明确。
- doctor区分“活着”和“与当前版本兼容”。支持报告只含允许的版本、平台和检查状态，不含端点、代理认证、私有模型、环境值、用户路径、原始日志、截图或识别文本。
- 图片文件入口也补齐了regular文件与256MiB编码字节上限；拒绝FIFO/设备及增长绕过，不把非阻塞标志夸大为对所有网络文件系统的硬实时期限。

## 使用

```sh
vellum build-info --json
vellum release status --json
vellum release install --bundle /path/to/trusted-bundle
vellum release rollback
vellum release repair
vellum release uninstall --yes
vellum support --json
vellum support --output support.json
```

校验和并非独立发布者认证。正式候选工作流要求固定标签/提交、干净构建和来源匹配，并生成构建来源证明；本轮没有实际运行GitHub工作流或公开发布。
