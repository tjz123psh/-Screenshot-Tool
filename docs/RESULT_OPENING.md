# 选区工具栏的结果窗口延迟

本轮针对“框选之后，点击选区旁的钉图、OCR、翻译时先顿一下再出现”，不是查看器内的按钮或直接启动演示窗口。

## 实现

- 普通区域截图复用本次截图已经初始化的 GTK 应用，移除旧选区层后，用内存中的成品/编辑文档建立结果窗口。正常成功路径不再中转 PNG、同步恢复文件、启动第二个 GTK 进程或重新解码文档。
- 后台为每个普通选区提供独立的匿名 UnixDatagram 完成通道。结果窗口首帧完成后才发送明确消息；仅该次截图解除占用。结果留着时仍可继续截图，旧结果退出不修改新截图状态。
- 通道没有公开 socket 路径，跨 CLI exec 后由 UI 恢复 CLOEXEC，截图/OCR 子程序不继承；EOF、无效消息都不能视为完成。旧后台未提供能力、长截图及错误恢复继续使用原交接流程。
- OCR/翻译保持独立结果的关闭语义、可编辑文档身份和遮挡后的快照，识别工作在首帧后安排。未遮挡原图不成为识别/导出捷径。
- 拆除旧选区窗口和输入法控制器的强引用环，解除全屏背景和完成计时器的持有。结果进程只需保留自己的选区，不应因截图界面的引用环保留整屏原图。

## 验证口径

本地仅进行格式、脚本、打包测试；完整编译和 Rust 测试在 CI 进行。额外在 CI 的隔离 Xvfb 上显式运行首帧调度、选区图像释放、独立 OCR 关闭测试，并要求 GTK 可用，不能无显示器跳过后算作已验证。这些 X11 控件回归不等于 Wayland 实机验收。

设置 VELLUM_TRACE 时，日志记录 toolbar-*-pressed、selection-overlay-closed、toolbar-result-first-frame；Pin 另记 pin-image-first-frame，区分空窗口和真正画出图片；OCR 另记 text-window-first-frame。这里只记固定阶段和时间，不记录截图内容、识别文本或端点。

上述 first-frame 指 GTK 客户端 after-paint，不等同于显示器呈现反馈。实机对比必须真正拖选、点击选区工具栏，覆盖首次进程和重复打开，单独记录外部可见条件，不能用演示窗口、map 回执或 OCR/网络完成时间替代。

## 保持不变的边界

- 不修改桌面快捷键或服务的 KillMode。
- IPC stop 不会终止已释放的结果进程，但 systemd 重启/升级具有不同的 cgroup 生命周期；安装仍要求先关闭活动窗口，不能承诺重启服务保留它们。
- 异常开窗仍保留原成品并走原持久化交接/内存恢复。识别错误可在结果窗口重试；不删除原有交接的封印、成品一致性或持久化检查。
