# 精修与快速滚动可靠性复查

本轮继续处理用户提供的平灰工作台与烟灰玻璃参考图之间的差距，同时复查快速滚动丢内容和全局快捷键。修改位于构建目录，未覆盖安装版、未修改桌面配置或系统服务。

## 长截图：已复现并修复

- 第一张持久采集帧在抓取中收到完成请求时，原来只留在局部 pending 中，退出循环后丢失；现在进入统一的 latest 交接，mock 回归证明只抓一次并保留全部像素。
- 滚动到最远处再反向、小关键帧预算时，原来在线已有 800 行，结束后可能变成 600 行。现有关键帧会提升转向保护优先级；关键帧集合和最终图路径都必须覆盖已采集的两端。检查的是输入空间覆盖，不用输出高度强行阻止有效纠错。
- 原来 240 高视口中，79 行重叠能通过，80 行反而失败。边缘裁除现改为平滑增加且不得侵占最少可信行，普通/稳健 RGB 和行签名共用边界；RGB 门限与假运动检查没有放宽。
- 损坏画面后的恢复曾错移 204 行；当局部历史被损坏帧干扰时，允许用整个稀疏视口完全相等的已保存画面重新定位，不允许仅凭局部相似绕过运动检查。原有回归加强为逐帧位置和高度检查。
- 离线重建逐张解压，最多同时持有参考帧和当前帧。160 张 512×256 夹具的解压像素峰值从 60 MiB 降至 0.75 MiB；这是解压帧开销，不是进程总内存。展平画布不再先克隆所有块，成功重建也不再提前分配完整在线备用图。
- 队列同时限制 48 帧与 96 MiB RGB 载荷；一张超预算帧可独占空队列以避免死锁。latest、正在处理的帧及最终长图不算在此预算内。满队列保留已拥有帧并暂停采集，不做静默丢帧；新饱和停止测试验证 48 张 FIFO 和第 49 张尾帧各被保留一次。
- 记录队列字节峰值、等待次数/时长、成功抓取间隔；一个未接上的画面随后静止，也会按时间更新提示，明确建议往回滚，而不是永远显示“校准中”或声称继续向前就能补齐。

## 视觉

- 工作台由 640×450 小幅增至 700×490。烟灰透明底、双层细边、顶部光泽、柔和金属按钮、内凹字段；侧栏淡入切换 160ms，按钮 hover/active 有独立反馈。
- 图标保留 SVG 给 GTK 按显示缩放渲染，不再先固定栅格化成 24px 再拉大。
- 截图和标注工具栏统一石墨/暖金材质、快捷键小标签、细线图标；选区边缘和大小滑块也统一暖色，保持深色外衬以在白底可见。图像像素本身不受主题染色。
- 真正的合成器截图通过自生成背景窗口取得，仅采集本程序覆盖范围；未拍摄用户桌面内容。截图底纹是测试背景，不是植入应用的壁纸贴图。

## 快捷键

应用授权与“已有桌面绑定（只读）”分开显示。配置中检测到的组合键不等于已验证按键触发；现有扫描器可能包括未加载文件，这个局限写在界面中。扫描输出只保留已知动作和合法按键，丢弃路径及原始命令。设置页不再提供写入合成器配置的按钮；既有 CLI 的兼容操作没有被自动调用或删除。

修复空授权后启用无效、停用后的迟到 Configure 错误污染状态、相同阶段的新消息不刷新、旧轮询覆盖刚点击的反馈。版本 1 不伪装支持版本 2 的 ConfigureShortcuts。

本机 niri 26.04 + GNOME 门户仍缺少实际绑定所需的桌面桥接，不能通过修改应用界面凭空补齐。现有手工桌面绑定未改动；没有进行新的真实授权或物理按键触发验收。

依据：[XDG 标准](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.GlobalShortcuts.html)、[niri 尚未合并的 GNOME 桥接提案](https://github.com/niri-wm/niri/pull/3587)。

## 不能承诺的边界

任意速度、任意页面“绝不丢帧”仍不成立。排队等待时，目标应用可能继续滚动；未被采集且没有足够重叠的内容无法凭空恢复。完全重复内容、异步加载、滚动到未加载区域仍可能被安全拒绝。真实采集夹具证明已捕获内容的完整性，不是所有网站的速度上限；其绘制与消费共享 GTK 主循环，不作为独立目标应用无限吞吐的证据。多屏、混合缩放和 Hyprland 未做本轮实机验收。
