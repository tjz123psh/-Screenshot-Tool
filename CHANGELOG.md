# Changelog

All notable changes to vellum are documented here. The Rust rewrite starts a new version series rather than continuing the retired Python implementation's releases.

## [Unreleased]

### Added

- Restyle the whole settings panel into a modern dark desktop app: a three-layer material system (deep window base with a soft top light, translucent card surfaces with hairline borders and a top inset sheen, sunken input insets), an indigo accent (`#4f6ef7`) replacing the washed-out periwinkle, and status shown as a glowing dot in a low-saturation pill.
- Turn the settings window into dark crystal glass: it is now genuinely translucent (`rgba(13,16,23,0.82)`) so the compositor's backdrop blur shows the wallpaper through it, lit by two stacked gradients — a soft sky light from above and a diffused indigo/violet aurora in the upper-right. Cards gain a specular top edge and a cast shadow, and the accent moved from `#4f6ef7` to the more saturated `#4361ee` (hover `#5271ff`, active `#3851d0`).
- Give the panel real motion instead of 0 ms state jumps: one `180ms cubic-bezier(0.16,1,0.3,1)` transition covers background/border/colour/shadow/opacity on every interactive control, buttons dip on press (`transform: scale(0.985)` with an inner shadow), inputs answer focus with a spreading accent halo, and the status dot breathes on a 3.2 s keyframe loop. Scrollbars rest at 4 px and widen to 7 px on hover over 240 ms.
- Scope the translucency to `.vellum-glass`, which only the settings window carries. `.vellum-window` is shared with the pin and result windows and `.vellum-card` with the long-shot panel, so the base rules stay opaque — a mostly-transparent window would have let captured pixels show through the text. A test asserts the shared rules keep an opaque background.
- Recolour the settings panel from dark crystal to warm glass: cream translucency over an amber aurora, cream cards and sunken warm-white inputs, dark ink for text, and an amber accent replacing the indigo. The pin, result and long-shot windows keep the dark palette: the panel is also the only window with `.vellum-glass`, so the warm rules are scoped to it and a test fails if a warm colour escapes that scope.
- Refine the warm panel into "champagne frosted crystal": `rgba(252,248,242,0.74)` glass lit from above with a champagne aurora, white-jade cards (`rgba(255,255,255,0.52)` with an `inset 0 1px 0 rgba(255,255,255,0.95)` top facet), and espresso-charcoal ink (`#241c16` titles, `#2b2119` labels). The idle status dot becomes an oat dewdrop (`rgba(160,135,110,0.70)`) instead of an electric blue spark, success turns warm jade (`#288c56`), the segmented control's checked state is a white jade tile, and the primary button is the sunset-caramel gradient `#d87a22` → `#b85d10`. No blue-dominant colour remains anywhere in the panel scope.
- Fix the invisible panel title: `.vellum-title` is `#ffffff` in the global rule (correct for the dark result window), so on the cream panel "设置" rendered white-on-white — 0 dark pixels, measured. The same failure mode hit every label that inherited the shared rule's `color: #f8fafc`. The panel now overrides both, and two tests fail if the title ever regresses to light ink or if an inherited near-white would vanish on the cream surface.
- Fix a cascade leak the warm panel exposed: the general scoped button rule's specular `inset 0 1px 0 rgba(255,255,255,0.90)` was painting a near-white 1px line across the top of every *unselected* sidebar item, because the nav rule declared only some of the properties the broader rule also sets. The nav rule now declares them all explicitly, and the same fix removes the white tile that had grown around the password reveal eye.
- Rework the two model prompts around a system/user split. Everything invariant — the rules, the target language and the glossary — travels in a `system` message, and the payload is the user message on its own. That last part matters more than it looks: an earlier draft wrapped the payload in `<text>` delimiters, but a screenshot that literally contains `</text>` would end the data region early, and the message boundary cannot be forged by anything inside the text. Reasons for the split at all: models weight a system instruction above user content, which matters when the payload is arbitrary on-screen text that can itself read like an instruction, and a constant prefix is what providers cache. Verified live against the configured endpoint: a plain UI string translated, and with a glossary the terms were honoured exactly (`Nexus` kept verbatim, `Vellum`→the pinned wording, `API`→the pinned wording).
- Add `[llm].glossary`: comma-separated terms that either stay verbatim (`Nexus`) or are pinned to one wording (`API=接口`), with a field in the translation card. A screenshot is full of text that must survive translation — identifiers, paths, flags, product names. Empty entries are dropped, and unlike model ids these are never run through the legacy-prefix stripper.
- Stop returning truncated answers as translations. The chat client now reads `finish_reason`: `length` raises a distinct error instead of shipping half a translation that looks complete, and it advances to the next configured model (a bigger one may fit); `content_filter` reports the upstream refusal. The API-OCR path falls back to the local engine on the same signal.
- Strip the one wrapper that is unambiguously chat formatting — a leading `译文：`/`识别结果：` label — in a shared implementation used by both the translation and the OCR path. Deliberately labels-only: a fence or a pair of quotes spanning the whole answer may BE the content (the translation prompt promises to preserve code blocks, and a screenshot of Markdown is itself a fenced block; a captured JSON fragment is `"production"`), and removing it is silent data loss the user cannot detect by looking at the result. An earlier draft of this change did strip fences and quotes; that was a bug, and the negative cases are now pinned by tests.
- Grey out the OCR rows that only affect the built-in engine, and say so accurately. `放大倍数`, `图像预处理` and the Tesseract language pack do not shape the API attempt — `recognize_api()` hands the raw crop to the vision model — so they are disabled under it. They are not dead settings, though: `recognize()` falls back to Tesseract whenever the vision call fails, and that path does read them. The hint says "内置引擎离线可用，API 失败时也回退到它；下方三项只作用于内置引擎" rather than claiming they do nothing.
- Fix the settings panel silently wiping `[llm].glossary` on save. `FormValues::from_config` filled the value and `values()` read it back, but `FormWidgets::populate` never wrote it into the entry: opening the panel showed an empty field and the next save stored that emptiness. A widget-level round-trip test now covers every field by name, and it fails with `left: ""` when the populate call is removed.
- Fix latent flakiness in every GTK-dependent test. GTK may only be used from the thread that initialised it, and the harness runs each test on its own thread, so two tests calling `gtk4::init()` raced — whichever lost panicked with "Attempted to initialize GTK from two different threads". They passed before only by luck of harness thread reuse; adding a third such test made it deterministic. `#[gtk4::test]` is the upstream answer but panics when GTK cannot start at all, and CI runs headless, so the tests now share one dedicated worker thread that reports a missing display as "unavailable" and lets each test return early.
- Stop reading a URL in a glossary entry as a `term=译法` mapping. `https://host/?a=b` contains an equals sign, and splitting on it produced a rule the user never wrote; an entry is only treated as a mapping when the left side is a plain term.
- Make the settings panel an independent window instead of a layout participant. It is now built with `resizable(false)`, which hands the compositor a fixed-size hint: measured on Hyprland's scrolling layout, a resizable panel maps as a tiling *column* (926x996) first and scrolls the whole desktop sideways (a browser window moved 940px), and the float requested 60 ms later removes the column but leaves the scroll. With the fixed-size hint the compositor floats it from the first frame — verified over three open/close cycles with the background geometry unchanged — and no compositor window rule is needed. The pid-based float call is kept as a fallback for a compositor that ignores the hint.
- Clear GTK's own focus outline inside the panel: the default theme paints it in electric blue *on top of* the amber ring this theme draws with box-shadow, so a focused field still measured `rgb(124,169,214)` across 237 pixels of the picker's search box. The warm scope now sets `outline: none` and draws the amber ring instead — including for keyboard focus on buttons, which the global `button:focus-visible` rule would otherwise paint blue. The panel now measures zero cold-blue pixels.
- Fix the model picker's dropdown button selector: a `Gtk.MenuButton`'s CSS node is `menubutton`, not `button`, so `button.vellum-picker-button` matched nothing and the warm styling never applied to it or its chevron.
- Repair three of the theme's own regression tests, which could not fail: one listed signature colours that appear nowhere in the stylesheet (so it skipped every rule), and two took the first match of a selector occurring many times and therefore inspected a dead rule. They now resolve the actual cascade through a small CSS matcher, and each is verified to fail when the bug it guards is reintroduced.
- Raise the panel's secondary text opacity for the light surface: the dark theme's alphas (`0.42`–`0.60`) landed at 2–3.7:1 on cream, below the 4.5:1 bar, so they are now `0.62`–`0.84`, with the amber warning ink darkened to `#8a5206`.
- Verify the GTK feature set the new theme depends on rather than assuming it: a control experiment proved `connect_parsing_error` really does report unknown properties, which is what makes the zero-error assertion meaningful, and a second test pins that this build accepts `transition`, `@keyframes`, `backdrop-filter`, layered `background-image`, gradient `border-image` and `transform`. `::before`/`::after` are rejected by GTK 4 and are therefore unused. `CSS_VERSION` is bumped (to 10 at that point; the panel restyles in this batch end at 12).
- Replace the panel's centred top tabs with the classic master-detail layout: a 184 px sidebar (模型接入 / 翻译与 OCR / 截图行为, mutually exclusive, keyboard-reachable) beside a content column whose forms are capped at 640 px, so a URL or proxy field no longer stretches across the window. `Ctrl+1`/`Ctrl+2`/`Ctrl+3` switch pages and keep the sidebar in sync.
- Rebuild every field as an Action Row — name and one-line description on the left, control on the right — with hairline separators between rows. New shared widgets live in `crates/vellum-ui/src/controls.rs`: action rows, cards, the embedded-eyebrow secret field, the compact stepper, secondary and primary buttons, status dots/pills and the segmented control.
- Move the API key reveal inside the field (a borderless eye toggle instead of a detached 显示 button beside it), lighten the steppers into one inset shell with the unit spelled out ("秒", "倍"), and drop the floppy-disk icon from the save button.
- Quiet the developer-facing copy: the `HTTPS_PROXY`/`ALL_PROXY`/`none` rules moved from a paragraph under the proxy field into its tooltip and placeholder, the "上面留空时读它" note is gone, and the title's redundant subtitle is removed.
- Style the settings controls the way GTK actually names them: a grouped `GtkCheckButton` exposes its indicator as `radio`, not `check`, so the OCR engine choice now renders as a clean segmented control instead of two leftover radio dots (a CSS rule targeting `check` silently matched nothing).
- Add a CSS regression test that parses the stylesheet through GTK and fails on any parsing error, plus a test asserting every class the panel and picker apply still has a rule in `theme.rs`; `CSS_VERSION` is bumped (to 9 at that point).
- Add `install-remote.sh`: a `curl | bash` one-liner that stages the source in a temporary directory, runs the in-tree installer and removes every trace on exit.
- Name the translation path in the result window footer (which API model answered, or that the text was already in the target language), as `ARCHITECTURE.md` §2.4 requires.
- Add a settings panel (`vellum panel`, the tray menu entry "设置面板" and a desktop entry) that configures the model API, translation, the OCR engine and the capture preferences. Its header is a drag handle, so the window can be moved with the mouse.
- Add an OpenAI-compatible API client (`crates/vellum-text/src/api.rs`) shared by translation and API vision OCR, including a hand-written base64 encoder for image data URLs and a `GET /models` probe behind the panel's connection test.
- Add 「获取模型」 to the panel: it requests `/models` and fills two searchable model pickers (translation and OCR vision) that also accept free text. The pickers strip the endpoint's path prefix (`models/…`) for display but commit the exact id, dedupe repeats, ellipsize long ids with the full string in a tooltip, follow the entry's width, and drive a keyboard cursor with ↑/↓/Enter/Esc; a typed name that the endpoint never reported is called out as a hint rather than an error, because gateways do serve models their `/models` never lists.
- Restructure the panel: model fields live on the 模型接入 page, translation and OCR merged into one scrollable 翻译与 OCR page, section cards with a footer bar, thinner scrollbars, a subtle window sheen, radio-style engine buttons, `Ctrl+1`/`Ctrl+2` page shortcuts and `Ctrl+S` to save.
- Fix the model picker's first mouse-open showing an empty list: the refill was hung off `MenuButton::activate`, which a click never emits; it now runs on `popover::map`, which also measures the popover width.
- Add an HTTP proxy setting (`[api] proxy`, panel field): empty reads `HTTPS_PROXY`/`ALL_PROXY`/`HTTP_PROXY`, `none` forces a direct connection. A blocked endpoint (OpenAI, Google) previously failed as an opaque timeout with no way to route it through the user's own proxy.
- Report a reachable endpoint whose `/models` list does not contain the configured model (for example `gpt-4o-mini` against Google's OpenAI-compatible endpoint) instead of letting it fail later with a 404.
- Offer two OCR engines: the built-in offline Tesseract pipeline, or a vision model over the same API endpoint.
- Count text rows before choosing the single-line page segmentation: a small wrapped paragraph has the same box shape as a banner, and PSM 7 on it used to return nothing and pay for a second Tesseract start (measured 1.0 s -> 0.52 s on a clean three-line crop).
- Ship window rules for the panel in the niri/Hyprland examples, plus `ai.vellum-panel.desktop`.

### Changed

- Restyle the screenshot overlay chrome to "Deep Obsidian Crystal". The control bar was flat with a hard 9 px corner and single-pixel buttons; it is now a translucent obsidian slab with a 13 px corner radius, a two-layer diffuse shadow (a tight 2 px contact pass at 0.32 plus a taller 5 px ambient pass at 0.18, both drawn before the body so the slab stays translucent over the dimmed desktop), a vertical crystal gradient (`#10141C` 0.97 to `#0B0D13` 0.98) and a three-stop specular edge that reads as a top-lit facet: white 0.22, cold blue 0.08 at 35 %, and a dark 0.45 inner base. Buttons became uniform 8 px ghost tiles — a 0.035 resting fill with no border, a 0.11 hover fill with a 0.14 rim, a 0.70-blue toggled state, and a red 0.20 hover tint on 取消 so the destructive exit reads as one. Primary actions (完成) keep a filled indigo gradient with a 1 px highlight edge, and shortcut hints moved into 4.5 px keycap badges with a 0.07 fill, a 0.12 rim and `Sans Bold 7.5` silver ink. The selection frame gained a dark backing line behind its 2 px indigo body plus a 1 px halo, because a bright screenshot used to swallow the frame entirely; handles shrank from 9 px discs to compact 4.5 px white cores with a 1.5 px indigo ring on a dark seat, still well inside the unchanged `selector::HANDLE_HALF` grab radius. The size chip, popups and hint rails now reuse the same slab recipe, so the overlay reads as one design instead of a bar with floating stickers.
- Improve long-shot reconstruction across repeated content, reverse scrolling, history revisits, fixed regions and local animation without relaxing acceptance thresholds.
- Improve OCR preprocessing and candidate ranking for dim, colored, gradient and isoluminant text.
- `install.sh` now removes the cargo build tree after a successful install, since an end-user install never rebuilds; `VELLUM_SKIP_CLEANUP=1` keeps it for incremental rebuilds.
- Drop the `panic` override from `[profile.bench]`: cargo ignores it for bench targets and printed a warning on every benchmark run.
- Retry a transient `accept` failure a bounded number of times instead of exiting the control service, and document the measurement dates, cross-references, visual tokens and per-variable trace semantics the audits found stale.
- Translation is API-only: the `opencode serve`/`opencode run` backends are gone, and a legacy `opencode/` model prefix is stripped while loading so a migrated config does not 404. `[api]` is now the shared endpoint (base URL, key, key environment variable, timeout); `[ocr] engine` accepts `builtin`/`api` (the old `tesseract`/`vision` names still load).
- The configuration file can now be written by vellum: `Config::save` renders a commented document and replaces it atomically with mode 0600, because it may hold an API key.
- `vellum doctor` reports the configured model endpoint, model and key source instead of looking for an `opencode` binary.

### Fixed

- Fix Chinese (and any composed) text being impossible to type into an annotation label: the overlay had no input-method context at all, so fcitx5 was never consulted and only ASCII ever appeared. The label editor read raw keyvals out of its key controller (`key.to_unicode()`), which cannot work with an input method by construction — a composition is not a key, and once fcitx5 is composing, the keystrokes that build the composition are not the characters the user wants. The annotation "text field" is a drawing area rather than a GtkEntry, so GTK never created a context on its own; one is now created explicitly and driven by the annotation state. Verified on this machine: with `GTK_IM_MODULE=fcitx`, creating and focusing the context makes GTK dlopen `/usr/lib/gtk-4.0/4.0.0/immodules/libim-fcitx5.so` (confirmed in `/proc/self/maps`), which the previous code never did.
- Draw the input-method composition in the label while it is being typed, underlined, so pinyin is visible before it is committed; a commit may be several characters at once and is inserted whole. The composition is held apart from the label text, so cancelling or re-composing it leaves no fragments behind, backspace inside a composition cannot delete an already-committed character, and it is never baked into the captured image.
- Keep the input method attached to the key controller **only** while a label is being typed. This is load-bearing rather than tidiness: GTK focuses an attached context by itself as soon as the controller's widget has focus (see `gtk_event_controller_key_handle_crossing`), and a focused context is exactly what makes fcitx5 start composing. Left attached, it would swallow the single-letter tool hotkeys — `d` for 标注, `o` for OCR and the rest — during plain selection, when the user is not typing text at all. GTK's `gtk_event_controller_key_handle_event` returns before the app's handler whenever the context filters a key, so a stolen hotkey would simply never arrive. Also anchors the candidate window to the label's caret instead of the corner of the output.
- Fix four latent Cairo path bugs the overlay restyle surfaced, found by adversarial review with mutation testing. `fill_rounded`, `stroke_rounded`, `fill_rounded_gradient` and `stroke_rounded_gradient` relied on `new_sub_path()` inside `rounded_rect`, which resets only the *current point* and leaves earlier sub-paths in the context — measured, a seeded rectangle survived into the next `fill()` at full alpha and was painted in the wrong colour. All four now clear the whole path. `draw_selection_frame` had the same defect for a different reason: `rectangle()` *adds* a sub-path, so the frame stroked whatever the annotator had left on the shared context before it (a seeded rectangle rendered at alpha 140). Also fixed: the 2 px frame body was snapped to a half pixel, which is the convention for an odd stroke width — being even, it smeared across three columns (measured `0,0,128,255,128,0` instead of a true `0,0,0,255,255,0`); the backing pass claimed to sit 1 px outside but a centred 3 px stroke put it 2.5 px out and 0.5 px into the body; and the separator, being *filled* rather than stroked, was half-pixel-snapped into a 2 px 50 % blur instead of a 1 px hairline.
- Fit the overlay toolbar to the output instead of letting it run off the edge. The restyle widened both bars by roughly 90 px while `layout` only clamped the bar's *position*, so on a 640 px output the annotate bar put 取消 and 完成 past the right edge — and because the overlay holds an exclusive keyboard grab, an off-screen button is unreachable by key too, leaving a mouse-only user without the exit. `layout` now measures first, then degrades in order of what the user loses least: tighten the gaps, then drop the decorative keycap badges. Labels keep their measured width throughout, so text is never ellipsised or overlapped; if even the tightest layout cannot fit, the bar clips as before. Covered by a test over ten output widths from 3840 down to 480 for both bars.
- Stop re-measuring the toolbar per frame in a way the cache was meant to prevent: `layout` cloned the whole measurement table on every call (`measure().to_vec()`), which runs on each draw. It now borrows the cached table and reads the geometry into scalars, so a frame allocates no measurement copy.
- Make the scale indicator on the 粗细 button honest: it clamped the stroke width to 4 px, so the two thickest settings (7 and 11) rendered identically to 4 and the swatch silently stopped reporting the current width. It scales instead.
- Strengthen five regression tests that could not fail, found by mutation testing (24 mutants produced only 4 failures across 122 tests). The hotkey test read the expected value out of the very table it was testing (`by_hotkey(spec.hotkey) == spec.id`), so replacing 11 of 15 shortcuts with nonsense passed everything; hotkeys and button order are now pinned as literal tables. The frame and handle tests asserted on cairo's current point, which `fill()` and `stroke()` clear on their own, so deleting every `new_path()` passed; both now assert on pixels. The backing-shadow test used a threshold one unit away from the un-backed value (249 vs a limit of 250), so deleting the entire backing pass passed; the margin is now asserted. The separator and the shape helpers likewise gained pixel-level guards, and each new assertion was confirmed to fail when the bug it guards is reintroduced.
- Fix the first screenshot after a reboot failing until the tray's "重启截图服务" was clicked. `vellum.service` is started at login by the *user manager*, and `After=graphical-session.target` does not order it after niri's own `systemctl --user import-environment`; the daemon therefore inherited an environment with no `WAYLAND_DISPLAY`, and every GTK action it spawned died with `Gtk-WARNING: Failed to open display` — exit 1, "Vellum 启动失败". Measured on this machine, boot 0: the service started at `16:24:34.463` and the compositor created `wayland-1` at `.782`. Restarting from the tray only worked because the manager's environment was populated by then. The display variables are now recovered where they are used: the control service resolves them from `systemctl --user show-environment` on the spawn path and passes them to each action through `Command::env`, retrying until the compositor has exported them, so the session heals itself without a restart; `vellum-ui` also repairs its own environment before GTK initialises, which covers the tray's direct-spawn fallback and the settings panel. Only *missing* variables are ever supplied, so an isolated `VELLUM_RUNTIME_DIR` session or a hand-started daemon is never repointed at the login session, and when a compositor exports no socket variable at all a single `wayland-*` socket in `XDG_RUNTIME_DIR` is used instead — two candidates are left untouched, because guessing would target another session's compositor.
- Install the long-shot finish signal handler before startup, ignore selection-stage presses and arm completion only after a valid region is confirmed.
- Require each screencopy frame to negotiate a supported current `wl_shm` buffer before `BufferDone`, preventing stale-buffer submission.
- Keep recorder controls and selection highlights outside sampled pixels, and fail closed when direct mode cannot expose a safe completion control.
- Treat a finish that beats the first frame (a second hotkey inside the overlay-to-recorder handoff, or 完成 during panel verification) as a user cancellation: it used to be reported as a capture failure, which fired a critical notification, exited 1 and made the daemon log a "startup failed (code 1)" event.
- Guard `systemctl --user daemon-reload` in `install.sh`: with an unreachable user manager (sudo, no session bus) the installer aborted after replacing the binaries but before the environment check and the build-tree cleanup.
- Update the locked `rustls` to 0.23.45 (and `rustls-webpki` to 0.103.15) to clear RUSTSEC-2026-0285, which the documented `cargo audit --no-yanked` gate flags as a medium-severity vulnerability. The workspace's direct-dependency pins are unchanged.
- Keep the persistent screencopy connection across a transient timeout: the move to grim is irreversible and costs a fork/exec per frame, so it now requires three consecutive timeouts (or a real protocol/geometry failure) instead of one.
- Stop vellum from floating a window that is not its own: the panel/pin/result float used to fall back to "float the focused window" when the compositor's client list had not caught up with the just-mapped window, which floated — and visibly shrank — whatever the user had focused (reported as "my browser shrank when I opened the panel"). The fallback is gone and the pid lookup is retried on the main loop instead; a miss now leaves the window tiled.
- Keep the tray alive on sessions that never activate `graphical-session.target` (this machine's Hyprland setup is one): the unit is now also installed into `default.target`, and the tray waits up to five minutes for the shell's `StatusNotifierWatcher` instead of dying inside systemd's restart budget. Without this, the tray — and with it the "设置面板" entry — never appeared after logging into Hyprland.
- Stop counting a daemon that is shutting down as available: `ping()` now requires `ok && running`, a non-accepted answer from a daemon that is not running falls back to an in-process action instead of dropping the keypress, and `vellum restart` waits for the old socket to stop answering before activating the new daemon.

### Testing

- Add `tests/install-systemd-unreachable.sh` (also run by CI): it drives the real installer with a stubbed toolchain and a failing `systemctl --user`, and fails if the install aborts before the environment check and the build-tree cleanup.
- Verify the previously environment-blocked Hyprland paths on 2026-09-18 now that the session runs Hyprland: compositor detection, shortcut discovery from the Lua config, pin window and settings panel self-floating without any user window rule, the tray's new panel entry activated through `com.canonical.dbusmenu.Event`, both ignored live tests (including the recorder zero-pixel fixture and its 130-frame damage-driven capture), and a translation round trip against a local OpenAI-compatible mock.
- Re-measure the documented gates on 2026-09-18 (niri 26.04, rustc 1.97.1): 101-frame stitch benchmark 129.1-143.9 ms opaque and 134.7-147.0 ms translucent, socket round trips p50 0.037-0.049 ms (ping) and 0.037-0.056 ms (status), niri screencopy plain copy 1.68-2.08 ms per 900x700 frame with damage-driven `capture()` pacing at the 144 Hz output cadence, long-shot trace overhead 7 ns/event disabled and 4-7.7 us per recorded frame enabled, both live ignored tests passing, and the OCR regression gate at 10/10 with 100% accuracy.

## [0.1.2] - 2026-08-01

### Fixed

- Serialize daemon completion, launch and shutdown so finished actions always run cursor/event/notification cleanup and no request can start after shutdown begins.
- Reap killed, detached and notification children instead of accumulating zombies in the daemon or tray.
- Reject non-executable PATH shadows, overflowing PPM dimensions and failed `pacman -T` dependency queries.
- Replace writable daemon test executables with stable shell fixtures to remove the parallel `ETXTBSY` race.

### Testing

- Add a deterministic synthetic OCR generator and scorer that uses only generated images and a developer-only local probe.
- Exercise installer query failures in isolation before cargo or user-file changes can run.

## [0.1.1] - 2026-08-01

### Changed

- Local OCR now adapts to faded text, uneven light/dark backgrounds, colored interference and isoluminant foreground/background colors using lazy CLAHE, polarity and color-projection candidates.
- Tesseract TSV confidence now drives preprocessing/layout selection, weak sparse-edge noise removal and per-line mixed-language fusion.

### Fixed

- Drain child stdout/stderr while writing stdin so large Tesseract or OpenCode output cannot deadlock and be misreported as a timeout; isolate their process groups so forked descendants cannot keep inherited pipes alive past the deadline.
- Keep sparse-noise filtering and mixed-language line fusion safe for multi-column text instead of dropping or swapping neighboring columns.

## [0.1.0] - 2026-07-31

### Added

- Complete Rust implementation split into seven crates and four purpose-built binaries.
- Region capture, annotation, local/vision OCR, translation, pin windows and a traditional dbusmenu system tray.
- Bidirectional manual-scroll long screenshots with fixed-region detection, local-animation rejection, bounded keyframes and validated offline rebuilding.
- Native niri and Hyprland window control, including floating pin/result windows and compositor-specific cursor handling.
- Lightweight JSON-over-Unix-socket control service and `vellumctl` hotkey client.
- Idempotent Arch Linux user installer, desktop metadata, icons, systemd user units and safe compositor shortcut integration.

### Performance

- Approximately 0.15 seconds for the 101-frame 900×700 long-shot benchmark.
- Approximately 0.04 milliseconds p50 for local control-socket ping/status round trips.
